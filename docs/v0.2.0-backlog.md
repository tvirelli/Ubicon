# v0.2.0 backlog

Non-blocking items to address in the next release. None of these stopped the
0.1.0 store reviews.

## Firefox (AMO) review warnings

1. **`strict_min_version` vs `data_collection_permissions`** (2 warnings, desktop
   and Android). The build declares `browser_specific_settings.gecko.strict_min_version`
   `128.0` (in `wxt.config.ts`), but the manifest also carries
   `gecko.data_collection_permissions`, which Firefox only supports from 140
   (desktop) / 142 (Android). AMO warns the min version predates that key.
   Fix options: raise `strict_min_version` to `140.0` (and set the Android min
   accordingly), or drop `data_collection_permissions` if it is not needed.
   Verify which WXT emits it before changing.

2. **Unsafe assignment to innerHTML** (3 warnings) in the built
   `content-scripts/content.js`, from `content/panel.ts`. The flagged spots use
   static template strings and set dynamic values with `textContent`
   afterward, so they are not actually injecting untrusted data, but AMO's
   linter flags any `innerHTML =`. Fix: build those nodes with
   `document.createElement` / `textContent` instead of `innerHTML` (the
   assign-panel skeleton, the db/custom tab bodies, and the result-item
   skeleton), so the warnings clear.

## Store submission checklist (lessons from 0.1.0)

- Each marketplace wants slightly different listing data. Keep a **separate
  store doc per marketplace** (Chrome, Edge, Firefox) rather than one shared
  file, so required fields and limits are tracked per store.
- **Chrome** needs a **marquee promo image (1400x560)** in addition to the
  small promo tile (440x280) and screenshots.
- **Description limit is 132 characters** on all three stores. Keep the
  manifest `description` in `wxt.config.ts` at or under 132 so it matches the
  listing and passes automated checks.
